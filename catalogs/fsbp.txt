# AWS Foundational Security Best Practices (FSBP) -- catalog of controls.
#
# Source: official AWS Security Hub CSPM pages
# (https://docs.aws.amazon.com/securityhub/latest/userguide/), fetched
# control by control (ACM, APIGateway, AutoScaling, CloudTrail, CloudWatch,
# Config, DynamoDB, EC2, ECR, IAM, KMS, Lambda, RDS, Redshift, S3,
# SecretsManager, SNS, SQS, SSM, WAF, Account) plus the full alphabetical
# listing of the framework for the remaining services (see this
# investigation's notes). Every line in this file corresponds to a
# control whose ID was read literally in that documentation -- no number
# was filled in by deduction or pattern.
#
# The MSK, Opensearch, Route53, SES, StepFunctions and Transfer controls
# come from a different, weaker source: they're the ones already cited
# by policies elsewhere, and those specific IDs weren't re-verified today
# against the AWS docs -- if any
# turns out to be wrong, the bug predates this catalog, it wasn't
# introduced by it.
#
# WHAT'S MISSING (on purpose, not by oversight): FSBP has more than 400
# controls and dozens of families that weren't even touched here --
# among others: Backup (beyond Backup.1), Bedrock, CodeArtifact,
# additional ELBv2, EMR beyond the 4 listed, Inspector, Macie beyond
# Macie.1, MQ, Neptune, NetworkFirewall, SageMaker (partial),
# SecurityHub, ServiceCatalog, WorkSpaces. A control absent from this
# file does NOT mean it doesn't exist in FSBP: it means it couldn't be
# verified in this session. If it shows up as "missing" in a coverage()
# run, it could be a real gap or a gap in THIS catalog -- worth checking
# against the official docs before assuming the former.
# complete: yes
#
